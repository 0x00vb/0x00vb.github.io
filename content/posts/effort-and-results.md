The user doesn't get the hours we put into a feature. They get whatever happens when they try to use it.

If an invoice takes too long to load, an impressive refactor doesn't make the wait shorter. If a retry charges them twice, the difficulty of the integration won't help much either.

That is the useful part of “society rewards results, not effort.” It forces a question: what changed for the person using this?

I wouldn't turn it into a theory of what people deserve. Access, timing, health, and luck affect results. A market outcome isn't a measure of someone's worth.

For engineering work, though, I want effort attached to an expected change. Faster requests. Fewer failures. A task someone can now complete. A restore procedure that actually works.

Some of those results stay invisible until something breaks. Fixing an authorization bug before it is exploited still counts. So does proving that a backup can be restored. The work needs an explanation of the risk it reduced.

Before spending another week, write down the expected effect and how you'll check it. Watch someone use the feature. Run the recovery exercise. Measure the slow request again.

Working hard is something I can choose. Whether the work helped is something I still need to find out.
